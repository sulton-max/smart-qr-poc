# v0.7 — Static content and export

*Last updated: 2026-07-19*

**Status:** 🚧 In progress · **Type:** Feature · **Started:** — · **Completed:** —

> **Rescoped 2026-07-18** — validation · unique-slug · info popovers · the model-shape remainder moved to `v0.9`; all four sit on surfaces the content-model v2 reshapes. What remains is barcodes + export.
>
> Content is one polymorphic `CodeContent` value object, backend-owned encoding, payload derived not stored. Detail: `../../content-model-rewire.md`.

### Iteration 1 — Static content types

- [x] Ability to create a code from a static content type — URL, contact card, WiFi network, calendar event, location, email, SMS, phone, and plain text — each with its own builder form.

### Iteration 2 — Barcodes

- [ ] Ability to create non-QR symbologies (Code 128, EAN, UPC, Data Matrix, PDF417, Aztec) from the builder.

### Iteration 3 — Export and print

- [ ] Ability to download a code as an SVG or PNG file instead of opening it in a browser tab.
- [ ] Ability to get a print-ready code — vector output with a sufficient quiet zone, error-correction headroom, and sizing guidance — that stays valid as later decorations are added.

### Iteration 4 — Builder correctness

- [x] Ability to preview the exact server-rendered code in the builder so it matches the downloaded asset.

### Iteration 5 — SDK sync

- [x] Adopt `@wow-two-beta/ui` `0.0.70` — response envelope, `ApiError`/`ProblemDetails`, Temporal dates, readonly collections.
- [x] Adopt camelCase enum serialization across the wire — fixed in the shared SDK method, published `WoW2.Sdk.Backend.Beta` `10.0.42-beta`.
- [ ] Adopt camelCase converters in SDK `Testing/ApiContracts` + `Codes/StyleSpecJson` — storage/test-side, one push each.

### Verification

- [x] Create a code from each content type → the scanned payload is correct.
- [ ] Create each barcode symbology → it renders and scans.
- [ ] Download SVG and PNG → files save (not a new tab); a print-ready export still scans at small print size.
